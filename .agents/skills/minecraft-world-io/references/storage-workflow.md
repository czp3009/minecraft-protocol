# World filesystem workflow

## Inventory paths from an official world

Inspect both official path-construction code and a world generated by the selected server. Account for:

- root `level.dat`, its previous/backup form, and temporary replacement behavior;
- player data and previous-player files, including their intentionally different fallback/promotion result;
- advancements and statistics;
- the `datapacks` directory, directory packs, ZIP packs, and the enabled/disabled selection stored in `level.dat`;
- saved data and dimension-scoped data;
- overworld, built-in non-overworld, and custom dimension directories;
- chunk, entity, and POI region directories;
- external region payload sidecars;
- the world directory lock.

Treat the repository-selected namespaced dimension layout as the only supported dimension directory shape unless an
explicit task changes that contract. Recovery siblings such as `level.dat_old` and player `.dat_old` files are file
recovery policy, not an alternate dimension layout. Keep resource-key to path mapping deterministic and reject unsafe
path components.

## Audit standalone files

For each official file family, establish:

- binary NBT, JSON, or another structured format;
- the exact selected-release root and field schema, including field names, types, presence conditions, nullability,
  defaults, dynamic identifiers, and intentionally raw subtrees;
- compression wrapper and detection behavior;
- absent-file result;
- format-intrinsic length fields and confirmation that no policy-sized read or decompression ceiling is added;
- direct write versus temporary-and-replace behavior;
- backup creation, corrupt-primary fallback, and promotion semantics;
- required durable flushes and cleanup after failure.

Separate intrinsic binary corruption from serializer/schema mismatch when a file family has a fallback. The former can
make a candidate unusable; the latter propagates without selecting, promoting, or preserving another candidate.

Use the maintained structured-data library for JSON and the NBT modules for binary NBT. Do not hand-escape structured
formats or parse NBT in this module.

Reconcile every library-provided serializable standalone-file model and custom serializer against those facts during a
Minecraft release update. A field the selected release always writes is required and non-null without a compatibility
default. Remove or reshape stale declarations instead of preserving an older schema, unless the task explicitly adds
historical compatibility. Verify both direct serializer use and official generate/rewrite/reload behavior.

For the selected-release built-ins, audit strong access to the world border, Chunk tickets, raids, and Ender Dragon
fight in every dimension where the official server emits them. Their common `DataVersion`/`data` root, generic
identifier path, compression detection, and logical coordination stay shared. The selected dimension's `data` child is
always the receiver; a named convenience method supplies only its saved-data identifier and payload type.

For data packs, keep inspection, one-file borrowed reads, complete archives, parsed packs, and enabled-world loading as
separate costs under the world facade's `dataPacks` child. Directory and ZIP paths must expose the same result and Okio
callback types. The enabled-world result retains the full persisted selection while this layer supplies only `file/...`
members; do not resolve bundled packs or silently apply server-start repository discovery here.

## Audit region stores

Verify region filename and coordinate mapping, random-access handle ownership, cache/open/close behavior, inline versus
external payload placement, sidecar replacement and cleanup, per-write compression choice, and failure recovery. Keep
format validation in `world-format`; translate only genuine filesystem failures at the I/O boundary.

When coordination or lifecycle changes, take the current module `AGENTS.md` and source as authoritative. Audit every
logical commit group, admission/close boundary, and final-reference cleanup with coroutine signals and gate-controlled
filesystem operations; do not infer correctness from delays, repeated stress, or a data race inside the test fake.
Fault-inject final flush and close failures: prove the initiating operation observes the failure, a same-key closing
waiter resumes only after cleanup, and the entry can be recreated. Prove the failure is not replayed by an owner close
that starts later, while a close barrier already sealed and waiting for that cleanup reports it to every concurrent
close caller without retaining failures from earlier completed operations.

Audit live read-only access separately as a bypass observer: it must take neither `session.lock` nor mutable per-file
coordination and never delay or mutate an official process's world. A caller-owned live Region handle may retain its own
`.mca` file across calls, but handles must share no world-level registry, file object, reference count, or lifecycle;
external sidecars remain per-Chunk resources. A header cached for one callback is only an I/O optimization, never a
freshness, atomicity, or header/payload consistency promise. Mutable stores must honor the directory lock and
deterministic close behavior defined by the public API.

## Use the existing official gate

The standard `world-io` interoperability scenario creates a world with the matching official server, closes it before
direct access, exercises standalone policies and mixed region compression, rewrites marked data through public stores,
and requires the official server to load, save, restart, and load it again. Extend this scenario only when the changed
behavior requires new cross-implementation evidence.

Do not add a custom launcher, a manual fixture task, a workspace-policy switch, or a separate success report. Keep
lower-layer malformed and boundary tests independent of the official process.

If artifact preparation, server startup, readiness, or workspace creation fails before the scenario reaches a storage
operation, route that failure to `buildSrc` or `minecraft-test-fixture-host`; do not change NBT, Anvil, or filesystem
behavior to mask a fixture incompatibility. Run `./gradlew :minecraft-test-fixture-host:test` when Fixture Host code
changes, then rerun the standard `world-io` task that owns interoperability.
